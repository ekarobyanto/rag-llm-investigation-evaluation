
Thesis Project Summary
Title

Analisis Komparatif Metode Sparse Retrieval, Dense Retrieval, dan Hybrid Retrieval pada Sistem Retrieval-Augmented Generation untuk Asisten AI dalam Game Investigasi

Research Objective

This research aims to compare three retrieval strategies used in a Retrieval-Augmented Generation (RAG) system for an AI assistant in an investigation game:

Sparse Retrieval
Dense Retrieval
Hybrid Retrieval

The comparison focuses on determining which strategy provides the best balance between:

Retrieval quality
Response quality
Real-time system performance

The research does not compare RAG vs Non-RAG. Every experiment uses RAG; only the retrieval strategy changes.

Research Questions

The study investigates:

How do Sparse, Dense, and Hybrid Retrieval compare in retrieval quality?
How does each retrieval strategy affect the quality of responses generated by the LLM?
How do the three retrieval strategies compare in terms of latency when implemented in a real-time investigation game?
Research Scope

The experiment isolates the retrieval component.

The following components remain constant throughout all experiments:

Knowledge Base
LLM (GPT-4o)
Prompt Template
OpenAI API
Chunking strategy
Evaluation method
Dataset
Ground Truth

The only independent variable is the retrieval strategy.

Knowledge Base

The knowledge base is implemented using PostgreSQL.

Core entities:

Suspects
Evidence
Case Ground Truth

Evidence is the primary knowledge corpus used by the retrieval module.

Each evidence document stores:

textual content
embedding vector
PostgreSQL searchVector

Thus one database supports:

Sparse Retrieval
Dense Retrieval
Hybrid Retrieval

without duplicating data.

Retrieval Strategies
Sparse Retrieval

Implementation:

PostgreSQL Full-Text Search

Uses:

searchVector
lexical matching

Strengths:

fast
precise keyword matching
entity matching

Weaknesses:

vocabulary mismatch
synonym limitation
Dense Retrieval

Implementation:

OpenAI Embeddings
pgvector
HNSW index

Uses semantic similarity rather than lexical similarity.

Strengths:

semantic understanding
synonym handling

Weaknesses:

higher computational cost
may miss exact keywords
Hybrid Retrieval

Implementation:

Sparse Retrieval

Dense Retrieval

↓

Reciprocal Rank Fusion (RRF)

Uses standard RRF.

No weighted fusion.

No neural reranker.

Purpose:

combine lexical precision with semantic understanding.

Evaluation Framework

Evaluation consists of three categories.

1. Retrieval Quality

Metrics:

Precision
Recall
Top-K Accuracy

These evaluate whether the correct evidence is retrieved.

2. Response Quality

Framework:

RAGAS

Metrics:

Context Precision
Context Recall
Faithfulness
Answer Relevance

Purpose:

Evaluate factual correctness and response quality.

3. System Performance

Metrics:

Retrieval Time
LLM Response Time
Total Response Time

Purpose:

Measure suitability for real-time investigation games.

Latency is intentionally chosen instead of token usage because the research focuses on efficiency in interactive environments.

Dataset

The system contains manually designed investigation cases.

Each case contains:

suspects
evidence
supporting documents

Evidence types include:

witness statements
forensic reports
financial records
CCTV logs
email messages
location reports
Ground Truth

Each investigation case includes a manually constructed Ground Truth.

Ground Truth stores:

correct suspect
relevant evidence IDs
contradiction pairs
expected investigation actions

Ground Truth is used for:

Retrieval evaluation
RAGAS evaluation
Final correctness validation

Future Work

Token usage and inference cost are not primary evaluation metrics in this study.

However, because the system already logs:

prompt tokens
completion tokens
total tokens
estimated cost

future research is recommended to analyze:

token efficiency
API cost
context compression
retrieval filtering
reranking
